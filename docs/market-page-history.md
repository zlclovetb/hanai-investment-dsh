# 今日市场历史记录

今日市场顶部可选择日期，或从“已保存历史日期”打开本地记录。“返回今日”恢复默认加载策略和开市轮询。选择今天的日历日期进入今日视图；若要查看今天已经保存的静态记录，从已保存日期列表选择今天。

## 保存与查看

- 默认加载复用 `isMarketOpen` 策略：窗口外先读取不晚于今天的最近一份可读本地归档，显示“休市快照”和记录日期；归档须覆盖最近应收盘工作日的八类面板。有精确来源时间的数据以当日 15:00 或之后的行情时间确认已收盘，获取时间须不早于行情时间；只有日期或无来源时间的面板须在当日 15:05 后取得。满足条件才直接复用，不请求行情源或改写原获取时间。指数还逐项检查，不能用最新一项掩盖保留的盘中旧项。
- 旧日期、盘中记录或缺失面板会触发一次自动取数并由现有 Host 路径更新归档，不启动手动冷却；失败时保留旧归档并提示。没有归档则正常取数，读取本地失败则明确报错。显式选择历史日期仍只读，不自动补实时数据。最近应收盘日按北京时间工作日推算，仍不等于完整节假日交易日历。
- 休市快照保留手动刷新按钮，点击才主动取数，并继续执行 60 秒冷却。自动跨过开盘边界时恢复行情轮询，显式选择的历史日期继续保持只读；休市快照的板块下钻只读已归档成分。

- 打开今日市场、开市自动轮询、手动刷新取得的成功结果均自动保存，不增加行情源请求。
- 当前归档包括指数与两市成交额、独立市场宽度、行业热力、概念热力、涨幅榜、跌幅榜、成交额榜、换手率榜。板块成分在实际下钻取得后保存。
- 大盘异动面板复用 `dsh-plugin` 的上证分时叠加板块异动展示方式：`market.intraday` 复用腾讯→东财分时链，`market.signals` 读取同花顺公开板块异动快讯。按 `intraday`、`signals` 两个面板 key 独立保存到统一历史表，快讯失败不阻塞分时和其它面板。两者均按实际分时交易日归档，历史缺失时明确提示，不请求实时接口补齐。
- 异动快讯保留当天各时刻事件，不再只取每板块最早一条或截取前8条；同分钟、同板块、同方向的重复快讯去重。板块名和方向取自标题的板块主句，排除午评、收评、外围行情和午休，不受后文个股涨跌干扰。只标注能对应上证分时分钟的同日事件，名称直接显示在图上，悬停查看原始快讯；行情来源与时间放在面板头中间。它是同花顺公开快讯标注，并非全市场扫描或参考站自有`market_yidong`的同源复制。
- 新归档带`method: ths-sector-events-v2`；默认视图会重新获取旧版截断的快讯快照，显式历史仍只读旧记录并注明不完整。公开新闻源独立受通用熔断保护，完整覆盖目标日期才接受空信号；分页最多8页且整次读取预算6秒，超出后保留上次快照。腾讯指数成交额/成交量不等于指数点位均线，因此不据此伪造均价线。
- 指数区域现有 8 个境内指数与 5 个海外参考指数。海外通过独立 `market.indices` RPC 批量加载，按 `global.indices` 面板复用同一张历史表；归档日期为北京时间观察日，每项保留自己的 `marketDate` 和原始来源时间，因此纳指上一美国交易日可以出现在今日观察快照中。显式历史模式不发海外实时请求。
- 海外新鲜度和轮询独立于 A 股：采用香港、纽约、东京、首尔与上海时区及各自工作日时段，纽约通过 IANA 时区处理冬夏令时；活跃时缓存25秒，其余6小时。各源连续失败3次冷却5分钟，失败沿用带原时间的旧值或显示不可用，诊断中独立列出“海外指数”。A50 仅用现货 `b_FTXIN9` / `100.XIN9`，不替换成期货或 CFD；黄金和原油不接入。
- 默认视图会分别寻找最近境内归档和最近海外归档；美股跨北京时间零点生成的海外单面板记录，不会遮蔽上一交易日的境内快照。旧的六指数归档会保留，新加品种未采集时显示缺失；默认视图可自动补新，显式历史视图不伪造补齐。
- 每个日期、每个面板保留最后一次成功记录；各面板独立更新，失败不会清空其它面板。它是每日面板快照，不是盘中逐笔或分钟回放。
- 归档日期优先使用来源时间，市场宽度使用其统计日期。缺少来源时间的板块、榜单和成分股仅在本次指数确认的市场日期、北京时间采集日与当前日期一致时归档，且必须为新取数结果；缓存不重新绑定日期。指数失败或日期不能确认时跳过这些面板，保留原归档，避免旧指数把新数据写回前一天，或旧缓存混入新日期。
- 境内与海外指数均按代码合并来源时间更晚的报价。部分返回时，成功取得的指数继续更新，缺失项保留各自原值和原来源时间；来源及行情时间范围集中显示在指数面板头。海外观察日使用批次原获取日期，跨午夜复用缓存不会生成新日期归档。两市成交额仅在本次有效结果同时包含沪深两个指数时计算，不能把新成交额与保留的旧成交额相加。
- 腾讯收盘报价可能因超过实时新鲜度窗口而标记 `stale`。明确来源时间更晚的收盘数据仍可归档，不能因为“不够实时”错过收盘快照。更新按来源时间比较；失败重试返回的同一快照、相同或更旧数据不能覆盖已有记录，来源状态和时间保持原样。
- 历史模式只读本地数据库，暂停行情轮询；切换热力、榜单或板块下钻不会调用实时接口。缺失日期、面板、成分会明确显示未保存，不用今日行情补齐。
- 历史从使用此功能后实际取得的数据积累。没有采集的过去日期不能凭日期选择器还原，也没有后台常驻采集或自动历史回填。

记录位于原数据目录 SQLite 的 `market_panel_snapshots` 表，按 `(date, panel_key)` 保存版本、来源、数据时间、保存时间和 JSON 数据。普通“清理行情缓存”不删除它，重启后仍可读取；没有自动删除旧日期的策略。

## 新增面板

复用按日期、面板存储，不为新面板新增数据库列：

1. 在 `packages/contracts/src/market-history.ts` 为面板定义数据契约、校验和唯一 key；加入 `MARKET_HISTORY_PANELS` 以参与完整性提示。
2. 在对应 Host 成功取数路径调用现有 `archiveMarketPanel`，传入原数据、来源和可确认的市场日期。独立 RPC 独立归档，不能让慢面板阻塞首页其它数据。
3. 在历史视图通过 `marketHistoryPanel` 读取所选日期；缺失时显示未保存，禁止回退实时 RPC。
4. 增加成功归档、失败不覆盖、跨日归属、历史无实时请求测试。面板 JSON 结构不兼容时升级版本并提供读取兼容，不能把旧记录直接当新结构使用。

日期列表和快照读取通过认证的 `market.history.list` / `market.history.get` RPC，客户端不指定文件路径或行情 URL。

- 后台运行依赖DSH宿主持续开启；宿主关闭时停止后续批次，并阻止未完成网络请求写入已关闭数据库。任务状态保存在宿主内存中，不自动跨重启续跑；每批结果和原始输入仍持久化，重启后手动启动即可从归档继续。
- 后台任务结束后，按北京时间完成日期把六项图表输入和本次任务结果整体归档到统一key `macro.chart`。这是生成日的观察快照，不是行情交易日；各分项保留原来的来源日期、获取时间和失败说明。同一天保留最后一次有成功数据的生成结果，全部失败不覆盖既有整图，清理缓存和宿主重启不删除整图历史。
- 显式历史日期优先回放当日整图快照，不再依赖分母与ETF必须归档在同一天；后续更新来源日期相同的面板不影响旧整图。旧版本只有分项记录的日期明确提示无法完整还原，不用今天的数据补造过去的生成结果。整图写入失败单独报告，不能把任务误报成全部完成。
- 分母的`checkedMonths`保留已有记录的归档依据，`refreshMonths`单独保存待复查月份；已补齐的旧月报数据可以先归档，下一批复查近期月份。六小时后或跨日重试不会再因撤销已检查月份却保留对应数据而触发“市场历史面板数据无效”。
