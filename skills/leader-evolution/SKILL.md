# 龙头是走出来的

把上一交易日的假设和今日事实逐项对账。输出题材内的总龙候选、次龙／卡位、中军／容量、补涨／跟风四层。每个候选带权重（1–5，题材内相对观察优先级）、低／中／高确信度、可执行证伪条件。保留并列候选和空层级。权重与确信度均不代表收益概率。

## 每次运行

1. 常规复盘先读上一交易日的收盘状态 JSON。首次使用明确建立基线。缺失上一日收盘状态时，说明断档并找回原档；建立新基线须明确标注。跟踪使用实际交易日，节假日按已知交易日历跳过。
2. 按 [输入与数据映射](references/input.md) 读 Hanai 冻结资料或用户提供的带时点快照。每条事实引用可核查来源。缺竞价、封板时点、完整板块归因或成交量时留空。判断强度、带动性、抗分歧和空间地位时，分别陈述直接证据及缺口。仅有个股涨停和相似属性时无法证明带动。
3. 用 [规则脚本](scripts/track.py) 跑收盘对账或盘中偏离。每日扫描昨日断板、大长腿、尾盘封板和放量一字后的弱转强。结合竞价量能、开盘半小时修复、缩量和题材负反馈，再核对封板质量是否否决升级。
4. 把脚本输出按「昨日判断复核 → 今日四层候选 → 框架外观察 → 节点提示」写成简短报告。盘中可以陈述偏离和截至时刻，保持候选、权重和确信度。收盘逐条报告上调、维持、下调、降级、撤销及其依据。框架外候选列明次日验证，符合准入条件时仅以低确信度加入。保留历史收盘 JSON 以便逐日对账，盘中输出单独保存。
5. L1 随日报。L2 单列，保留次日可直接核对的条件。收盘 L3 置于报告首条，即时呈达给当前用户，标出题材、事实和「停止在该题材内新开仓」。用户已接入并明确授权通知渠道时，呈达同一条 L3，按日期、题材、触发原因去重。后续误报作为新的纠错记录，保留原始输出。阈值校准记录样本和效果，以下一交易日起生效。
6. 用户要求把结果显示在 Hanai 时，用 `--publish-hanai` 发布收盘清算。需要阶段与节点时，在标准化输入的 `themes` 里附上有证据的收盘结论。保留相同题材名称，便于把清算、题材阶段和节点对齐。详细格式见 [输入与数据映射](references/input.md)。

脚本输出为事实判定和状态变更的权威。模型只能整理表达、注明证据质量和提出次日需验证的条件。涉及买卖的提示仅作用户决策约束，由用户决定是否执行。
